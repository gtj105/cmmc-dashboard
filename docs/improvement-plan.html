Automated Database Backups
DurabilityDone
Analogy: Before this, your compliance data was a notebook with no photocopies. If the notebook was destroyed, everything was gone. Daily automated backups are the photocopy in the fireproof safe.
What was built:
  • Dedicated backup Docker service (4th container) using Alpine + postgresql15-client
  • backup.sh — pg_dump daily at 2AM via cron, with SHA-256 checksum on every file
  • 30 daily backups + 12 weekly snapshots with automatic rotation
  • restore.sh with --list, --verify, --file flags and post-restore row count validation
  • Evidence volume (tar.gz) backed up alongside the DB dump
  • Weekly integrity verification every Sunday at 6AM (verify-backup.sh)
  • Dedicated backup_data Docker volume for backup persistence

CSRF Protection
SecurityDone
Analogy: CSRF is someone forging your signature on a check while you're logged in. The bank processes it because the session cookie looks valid. CSRF tokens prove the request actually came from your UI.
What was built:
  • Double-submit cookie pattern: cmmc-csrf cookie + X-CSRF-Token header
  • src/middleware.ts — sets cookie on every page load if not already present
  • src/lib/api-csrf.ts — checkCsrf(req) server-side validation
  • src/lib/api-client.ts — apiFetch() wrapper auto-attaches token (same signature as fetch())
  • All 11 mutating API route handlers updated to call checkCsrf() as first operation
  • All 8 frontend components updated from fetch() to apiFetch()
Nginx Rate Limiting
SecurityAvailabilityDone
Analogy: In-memory rate limiting is a bouncer who forgets everyone's face when they take a bathroom break. Nginx rate limiting is the bouncer with a clipboard at the front door — it survives app restarts.
What was built:
  • limit_req_zone in nginx.conf — process-level, persists across app restarts
  • API endpoints: 10 req/s, burst 20
  • Login endpoint: 3 req/s, burst 5 (tighter for credential stuffing protection)
  • Returns 429 Too Many Requests on breach
  • Separate zones for different endpoint types
  • Note: resets if nginx itself restarts (no Redis needed for current scale)
App Container Health Check & Service Dependencies
AvailabilityDone
What was built:
  • GET /api/health — no auth, used by Docker and admin UI
  • Checks: DB connectivity + query latency, evidence volume mounted, heap memory < 512MB
  • Returns 200 healthy / 503 unhealthy with JSON detail
  • Docker health check: every 10s, 6 retries, 40s start period
  • HOSTNAME=0.0.0.0 env var so Next.js standalone binds all interfaces
  • Health check uses 127.0.0.1 directly (avoids DNS resolution in container)
  • nginx depends_on: app: condition: service_healthy — nginx won't start until app is ready

Advanced Hardening ✓ Partial
CSP, Zod, session revocation, backup sanitization, and first-login password enforcement complete. Encryption at rest is future work.
Zod Input Validation on All API Routes
Security
Problem: API routes trust that incoming JSON has the right shape and types. Malformed or oversized payloads reach business logic without being validated at the boundary.
✓ Done: src/lib/validation.ts — centralized Zod schemas for all mutation routes (practices, POAM, objectives, users, password change). String length caps, enum guards, and date format validation. Routes return structured error messages on invalid input.
Full Content Security Policy Header
Security
Problem: The app had frame-ancestors 'none' only — no restriction on script/style sources. An XSS vulnerability could load external scripts.
✓ Done: Full CSP added to nginx.conf: default-src 'self', locked form-action, base-uri, object-src 'none', frame-ancestors 'none'. Allows unsafe-inline/unsafe-eval for Next.js RSC compatibility — nonce-based upgrade is future work.
Session Revocation on Logout
Security
Problem: JWT sessions had a maxAge but no server-side revocation. A stolen or lingering token stayed valid until it expired naturally.
✓ Done: Each JWT now carries a jti (UUID). On logout, the jti is inserted into a revoked_tokens table (auto-purged after expiry). Revocation is checked at the API layer on authenticated requests. Token maxAge set to 24h.
Backup Export Sanitization
Security
Problem: The JSON backup export included password_hash for every user. Anyone who got the file could attempt offline bcrypt cracking.
✓ Done: Export query now selects id, email, name, role, created_at only — password_hash is never serialized. After a restore, all users have must_change_password = true and are redirected to /set-password on first login.
First-Login Password Enforcement
Security
Problem: Admin-created users had no way to set their own password — they had to use whatever the admin typed, shared out-of-band.
✓ Done: New users have must_change_password = true. Middleware redirects them to /set-password on first login — they cannot reach any other page until they set a permanent password. Flag is cleared in the DB and JWT is refreshed on success.
Database Encryption at Rest
DurabilitySecurity
Problem: The pgdata Docker volume is unencrypted. If the host disk is physically accessed, database files are readable without credentials.
Solution: Enable filesystem-level encryption on the host (macOS FileVault, Linux LUKS). For cloud deployment, use encrypted EBS volumes (AWS) or managed PostgreSQL (RDS, Supabase) with encryption at rest enabled by default.

Security Hardening & Deployment Simplification — March 2026 ✓ Complete
Token revocation, DB-backed rate limiting, backup hardening, auto-migrations, entrypoint secret handling.
Token Revocation Enforced on Every API Request
SecurityDone
What was built:
  • getAuthSession() helper checks both revoked_tokens (per-token JTI) and user_invalidations (per-user) on every authenticated API request
  • Replaces scattered getServerSession() calls across all API routes
User Token Invalidation on Deletion
SecurityDone
What was built:
  • Deleting a user writes a row to user_invalidations table
  • Any existing JWT for that user is rejected on the next request — no waiting for token expiry
DB-Backed Login Rate Limiter (Survives Restarts)
SecurityDone
What was built:
  • Failed login attempts tracked in login_attempts table (email, count, locked_until)
  • 5 failures triggers 15-minute lockout; state survives app and container restarts
  • Cleared automatically on successful login
Zod Row-Level Validation on Backup Restore
SecurityDone
What was built:
  • Every row in an uploaded backup file is validated against its Zod schema before touching the DB
  • 10 MB file size limit on backup uploads enforced at the API boundary
  • Malformed or oversized payloads are rejected with structured error messages
Backup Password Hash Injection Blocked
SecurityDone
What was built:
  • Backup restore explicitly rejects any password_hash field in the import payload
  • All restored users are forced to set a new password on first login (must_change_password = true)
Timing-Safe CSRF Token Comparison
SecurityDone
What was built:
  • checkCsrf() uses crypto.timingSafeEqual to compare cookie and header tokens
  • csrfCookieHeaders() sets Secure flag only when NEXTAUTH_URL starts with https
Health Endpoint Error Masking
SecurityDone
What was built:
  • /api/health returns generic error messages to callers
  • Detailed DB error messages logged server-side only — never exposed in the response body
Evidence URL Validation (Scheme + Length)
SecurityDone
What was built:
  • Evidence URL fields validated: http/https scheme only, maximum 2048 characters
  • Other schemes (e.g. javascript:, file:) and overlong values rejected at the API layer
Auto-Migrations on Startup
AvailabilityDone
What was built:
  • Next.js instrumentation hook (src/instrumentation.ts) runs run-migrations.ts before the app serves requests
  • schema_migrations table tracks applied files; prevents double-application
  • No manual psql steps needed on first deploy or upgrade
Simplified Deployment (One-Command Dev and Prod)
AvailabilityDone
What was built:
  • start-dev.sh auto-bootstraps secrets if not present — no separate setup step
  • Production redeploy: git pull && docker compose up -d --build — migrations run automatically
Entrypoint-Based NEXTAUTH_SECRET for Edge Middleware
SecurityDone
What was built:
  • docker-entrypoint.sh reads the Docker secret file at startup and exports NEXTAUTH_SECRET before the app process starts
  • The secret is never written to .env in production — Edge middleware receives it via the process environment
  • In dev, setup-secrets.sh writes it to .env and Next.js auto-loads it
